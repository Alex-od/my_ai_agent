# Этап 2-3 — Сценарий демонстрации

## Важно перед каждым вопросом
Нажимать **"+"** (новый чат) — иначе история предыдущих вопросов накапливается, занимает токены и мешает поиску.

## Шаг 1: Показываем "Без RAG" (ChatScreen)

1. Открыть навигационное меню (иконка ≡)
2. Выбрать "Чат" (ChatScreen)
3. Убедиться что MCP **не подключён** (кнопка MCP без ●)
4. Задавать вопросы из списка по одному
5. После каждого ответа — открыть Логи (кнопка в тулбаре) → вкладка JSON
   - Показать: в `instructions` нет блока `=== КОНТЕКСТ ИЗ БАЗЫ ЗНАНИЙ ===`
   - Модель отвечает из общих знаний

**Что увидит учитель:**
- Ответ на Q1 ("технология для генерации текста"): модель перечислит GPT, LLaMA, Claude — но не скажет "Gemini Nano, AICore, Android 14+, Pixel 8+"
- Ответ на Q6 (spacing токены): назовёт стандартные 4/8/16/24/32 — но не значения xs/sm/md/lg/xl из проекта
- Ответ на Q10 (метрики eval): назовёт общие метрики без конкретных порогов (0.75, 0.85, ≤3000ms)

## Шаг 2: Показываем "С RAG" (RagScreen)

1. Открыть навигационное меню → выбрать "Неделя 5: RAG"
2. Убедиться что MCP подключён (MCP ●), индекс готов ("Готово")
3. Задавать те же вопросы в том же порядке
4. После каждого ответа — показать **RagResultsPanel** под панелью RAG:
   - Видно сколько чанков найдено и из каких файлов
   - Показать Source, Section, Score для каждого чанка
5. Открыть Логи → вкладка JSON:
   - В поле `instructions` виден блок `=== КОНТЕКСТ ИЗ БАЗЫ ЗНАНИЙ ===`
   - Видны конкретные фрагменты из файлов

**Что увидит учитель:**
- Ответ на Q1: "Gemini Nano через AICore, Android 14+, Pixel 8+" — точно из таблицы
- Ответ на Q6: "none=0, xs=4, sm=8, md=12, lg=16, xl=20, xxl=24, xxxl=32, huge=48, giant=64"
- Ответ на Q10: точные пороги "answer_relevancy ≥ 0.75, tool_call_accuracy ≥ 0.85"

## Шаг 3: Момент "провала RAG" (учебный кейс)

Задать вопрос общим языком, не совпадающим с терминологией документов:

> "как сделать приложение для нескольких платформ"

Ожидаемое поведение с RAG: чанки могут не найтись (семантически далеко от "Kotlin Multiplatform") — RagResultsPanel покажет нерелевантные чанки или "Ничего не найдено".

**Объяснить учителю:** это ограничение pure vector search — запрос должен быть семантически близок к тексту документа. Решение: hybrid search (векторный + keyword) или переформулировать запрос ("KMP", "Kotlin Multiplatform").

---

## Важный момент для учителя — формулировка запроса

RAG использует **семантическое сходство векторов**. Запрос и текст в документе должны быть близки по смыслу.

Пример провала:
- Запрос: *"мигрировать Android на Kotlin Multiplatform"*
- Документ: *"СТРАТЕГИЯ МИГРАЦИИ Android → KMP"*
- Проблема: топ-K заполнился другими KMP-секциями (структура, библиотеки), а нужная секция не вошла

Решения:
1. Увеличить Top-K (больше шансов захватить нужный чанк)
2. Переформулировать запрос ближе к терминологии документа

**Вывод:** качество RAG зависит не только от базы знаний, но и от того как пользователь формулирует вопрос.
